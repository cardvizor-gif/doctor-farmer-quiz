# Разделение суперпользователя и администраторов

## Целевая модель

Шамиль Вильданов определяется как единственный суперпользователь по защищённому `OWNER_OPEN_ID`. Это системное правило, а не редактируемое поле интерфейса. Даже пользователь с ролью `admin` не становится суперпользователем автоматически.

Обычный сотрудник имеет роль `user` и получает только назначенные permissions. Делегированный администратор имеет роль `admin`, но также действует в пределах явно назначенных административных permissions. Отдельная проверка суперпользователя требуется для операций, которые могут менять саму модель доступа.

## Полномочия

| Группа | Суперпользователь | Делегированный администратор | Сотрудник |
|---|---:|---:|---:|
| Рабочие разделы по назначенным permissions | Полный доступ | Только назначенные | Только назначенные |
| Просмотр состава команды и рабочих баз | Да | Только `team.read` | Нет |
| Изменение permissions сотрудников | Да | Только `team.permissions.manage`, без изменения ролей администраторов | Нет |
| Назначение роли «Администратор» | Да | Нет | Нет |
| Снятие роли администратора | Да | Нет | Нет |
| Передача базы и архивирование сотрудника | Да | Только при `team.transfer` и только для обычного сотрудника | Нет |
| Управление суперпользователем и собой | Защищено от потери | Нет | Нет |

## Серверные правила

Проверка суперпользователя выполняется на сервере сравнением `ctx.user.openId` с `ENV.ownerOpenId`; клиентский флаг и значение роли не считаются достаточными. Существующие процедуры, которые сейчас дают полный доступ любой роли `admin`, переводятся на явные permission-проверки. Только суперпользователь может назначать или снимать роль `admin`, а делегированный администратор не может редактировать другого администратора, владельца или себя.

Операция передачи базы разрешается суперпользователю. Для делегированных администраторов она может быть включена отдельным permission `team.transfer`, но только в отношении обычных активных сотрудников. Архивирование владельца, последнего администратора и самого оператора запрещено независимо от permissions.

## Интерфейс

В панели команды суперпользователь видит полный выбор роли. Делегированный администратор видит только разрешённые настройки обычных сотрудников, без возможности назначить роль администратора. Критические действия получают отдельные подписи и подтверждение. Скрытие элементов в интерфейсе является удобством, а все запреты повторяются в tRPC-процедурах.

## Обратная совместимость

Существующие записи с ролью `admin` сохраняются. Для них permissions не обнуляются автоматически: суперпользователь получает полный доступ системно, а делегированным администраторам права должны быть явно назначены в панели. До назначения административных permissions делегированный администратор не получает критических операций.

## Проверки

Нужны тесты на неизменяемость суперпользователя, запрет повышения роли для делегированного администратора, запрет изменения другого администратора, разрешённое ограниченное действие по permission и сохранение owner-scoped изоляции данных.

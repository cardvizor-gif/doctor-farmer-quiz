# План обновления Doctor Farmer на сервере `193.233.201.76`

## Цель

Обновить отдельный серверный экземпляр Doctor Farmer по адресу `http://193.233.201.76:3000` до текущей ветки `main` репозитория `cardvizor-gif/doctor-farmer-quiz`. Эта ветка уже содержит внутренние обращения с вложениями и ограничение доступа к тестированию только после регистрации.

## Текущая ситуация

Шамиль Вильданов уже вошёл на целевой Ubuntu-сервер под пользователем `root`; его приглашение оболочки — `root@soft-silver:~#`. Приложение ранее обновлялось из `/root/doctor-farmer-quiz` и запускается процессом `pm2` с именем `doctor-farmer`.

> Важно: сервер на IP-адресе — самостоятельное развёртывание. Обновление GitHub не применяет изменения к нему автоматически; на сервере необходимо отдельно получить изменения, собрать проект и перезапустить процесс.

## Последовательность действий

| Этап | Команда или действие | Ожидаемый результат |
|---|---|---|
| 1. Проверка перед обновлением | Перейти в каталог и проверить ветку, статус, удалённый репозиторий, процесс: `cd /root/doctor-farmer-quiz && git branch --show-current && git status --short && git remote -v && pm2 status doctor-farmer` | Подтверждены каталог, ветка `main`, доступный `origin` и рабочий процесс. Если `git status --short` не пуст, дальнейшие команды не выполнять до сохранения серверных правок. |
| 2. Синхронизация | Выполнить `git pull origin main` | Серверный репозиторий получает актуальный коммит из GitHub. При конфликте остановиться и не использовать принудительную перезапись. |
| 3. Зависимости и сборка | Выполнить `pnpm install && pnpm run build` | Зависимости соответствуют актуальному lock-файлу, production-сборка проходит без ошибок. |
| 4. Перезапуск | Выполнить `pm2 restart doctor-farmer && pm2 status doctor-farmer` | Процесс `doctor-farmer` возвращается в статус `online`. |
| 5. Диагностика при сбое | Выполнить `pm2 logs doctor-farmer --lines 80 --nostream` | Получены последние сообщения процесса для исправления причины, без бесконечного просмотра логов. |
| 6. Внешняя проверка | Открыть `http://193.233.201.76:3000` и обновить страницу без использования кэша браузера. | Интерфейс соответствует текущему кабинету; виден раздел «Обращения», а гостевой `/quiz` предлагает войти вместо показа заданий. |

## Команда обновления

Когда предварительная проверка покажет чистое рабочее дерево и ветку `main`, будет использована следующая команда:

```bash
cd /root/doctor-farmer-quiz \
  && git pull origin main \
  && pnpm install \
  && pnpm run build \
  && pm2 restart doctor-farmer \
  && pm2 status doctor-farmer
```

## Контроль и риски

| Риск | Действие |
|---|---|
| На сервере есть незакоммиченные правки | Остановиться после `git status --short`; сначала сохранить или обсудить эти изменения. |
| `git pull` сообщает о конфликте | Не применять `reset --hard` или принудительную перезапись; передать текст конфликта для безопасного решения. |
| Не проходит `pnpm run build` | Не перезапускать `pm2` и передать последние строки ошибки. |
| `doctor-farmer` не получает статус `online` | Проверить целевые логи `pm2` и конфигурацию запуска. |
| Браузер показывает старый вариант | Выполнить обновление без кэша; затем проверить, что процесс перезапущен после успешной сборки. |

## Критерии завершения

Работа считается завершённой, когда серверная ветка совпадает с `origin/main`, сборка прошла успешно, `doctor-farmer` имеет статус `online`, а по IP-адресу открывается актуальная версия приложения.

## Последующее исправление репозитория

На постоянном сервере вручную удалён необязательный скрипт аналитики, поскольку его переменные окружения не настроены. После подтверждения работы сервера это исправление следует отдельным коммитом внести в репозиторий, чтобы следующая синхронизация не вернула неисправную строку.

Внешняя проверка выполняется по `http://193.233.201.76:3000` с обновлением страницы без кэша после рестарта `pm2`.
